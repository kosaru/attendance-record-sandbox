1. 企画・範囲・全体像

道場生・同伴保護者が、自分または家族の出席をスマートフォンで確認する。約15道場・200名は将来規模。今回の試作は指定した少人数と架空の会員・試験用道場を対象とする。判断者と問い合わせ先は依頼者。

区分担当と情報の流れ
準備依頼者が参加者と道場を指定 → アプリでQRを用意 → 依頼者が配布 → 責任者が掲示
利用道場生・保護者 → Google本人確認 → 会員選択 → QR読取 → 自分の出席帳
保全通常保存 → 日次コピー → 非公開Drive。依頼者が結果確認・復旧判断・終了判断
既存運用紙の出席簿と責任者の別管理は継続。アプリと責任者管理の連携は試作対象外

実装技術を検討するための前提

対象現時点の方針・未検証事項
端末iPhone・AndroidのWebアプリ。ホーム画面追加。ログインとカメラは実機未検証。
本人確認・保存Googleログインを暫定採用。既存DigitalOcean＋SQLite、非公開Driveへ日次保全の方針。
運用・費用直近7日分を保全。最後の正常コピー以降は失われ得る。利用者無料、追加支出が必要なら依頼者判断。
対象外別Googleアカウント間共有、オフライン登録、過去出席の新規追加、一括出席、利用者の自由訂正。
公開DNS・公開設定は公開時まで保留。既存WordPressとの同居・空きメモリの余裕は未検証。
未定本番期限と提供判断、実装言語・API・物理テーブル・排他方式・配置手順。

3. 利用者と担当者の行動シナリオ

ID仕事人と情報の流れ
S01初めて使う（R01〜R03）道場生または保護者がURLを開く → Googleでログイン → 本人・子どもの記録対象を用意する。
S02道場で記録する（R03〜R06）利用者が出席する人を選ぶ → 掲示QRを読む → アプリが道場を識別し、重複を確認 → 保存完了後にスタンプと回数を表示する。
S03もう一度読み取る（R05）同じ人が同じ日・同じ道場のQRを再度読む → 既に記録されている出席を表示 → 回数は増やさない。
S04別の道場に行く（R05・R06）同じ日に別道場のQRを読む → その道場のスタンプを追加 → 年間回数も1回増える。
S05記録を見る・端末を変える（R06・R07）利用者がログイン → 本人または家族を選ぶ → スタンプと年間回数を見る。新端末でも同じアカウントで同じ記録を見る。
S06読み取りや通信に失敗する（R04・R05）不明なQRやカメラ拒否では登録せず、理由を案内する。通信の応答がなければ、成功したとは表示しない。
S07間違いに気付く（R04・R06）利用者が違う家族を選んで記録したことに気付く → 問い合わせ窓口の依頼者へ連絡する。
S08試作を準備する依頼者が参加者と試験用道場を指定 → 保守担当が参加許可とQRを用意 → 依頼者が配布 → 責任者が掲示。保守担当は依頼者の指示で作業する役割。
S09誤登録を直す利用者が依頼者へ連絡 → 依頼者が会員・道場・日付と理由を確認 → 保守操作で訂正・取消 → 履歴と表示・集計を確認。
S10保全して復旧する毎日コピーを作り非公開Driveへ保存 → 依頼者が成否を確認 → 障害時は依頼者が復旧を判断 → 最後の正常コピーを復元し件数と本人対応を確認。
S11試作を終了する依頼者が終了日を決定 → 終了後30日以内に通常保存・コピー・履歴・識別情報を削除 → 未完了がないか確認。

4. 概念データと仕事のまとまり

概念データ図 · 論理データの関係図 · 要求と確認条件の対応表

アカウント1件 → 会員0件以上。会員1件 → 出席0件以上。道場1件 → 出席0件以上。出席1件は必ず1会員・1道場に属する。同姓同名の会員を自動統合しない。

会員・出席の訂正履歴は対象種別で関連先を分ける。両方への必須関連としていた前版のERDは採用しない。操作確認情報は元の出席操作を追跡する補助情報。バックアップは復元用の複製であり新たな出席ではない。

5. 図の読み方と変更点

□ 区画付きの箱：画面／外部との接点✹ ギザギザ：処理を起こすイベント⬭ 楕円：機能円筒：論理データ

実線は画面・イベント・機能・結果の流れ。点線はデータ操作。Rはデータ→機能、C/U/Dは機能→データ。C＝作成、R＝参照、U＝更新、D＝削除。複数操作の矢印は機能が条件に応じて行い得る操作の集合であり、全分岐で全操作が成功する意味ではありません。

同じUI IDは別ページでも同じ画面です。図中の [1.2] は直後の対応表の行を示します。戻り操作も機能を介して接続します。@{…}は複数件の表示。E番号はその図内のイベント番号です。

前版の問題修正
27枚の孤立した同形図正常・例外を機能から分岐させ、同画面への戻りと仕事の入口・出口を接続
イベントが「成功・失敗」実際のクリック・読取・日次時刻に置換し、成功／失敗は結果に移動
画面名のみ、機能も四角画面に表示・入力・操作の区画。機能は楕円で描画
全データを一つの筒に列挙論理データごとに円筒を分け、参照・作成・更新・削除の向きを表示
CRUD列にInteraction IDを羅列行をWorkset、列をデータとしてC/R/U/Dを配置
検証済みを過大に表明実施した構造・参照・描画検査と、未承認の業務判断を分離

Mermaidは標準編集元として維持。楕円の表示はレンダー時にstadium形状をellipseへ置換する。書籍の意味を保つ表示上の変換で、データや遷移は変更しない。

ログインして利用を始めるCRR—————R—

QRで出席を記録する—RRCRCRU————
出席記録を確認する—RRR—————
試作利用を準備する——CR————CR—
誤記録を訂正する—RURRU—CR———
記録を保全するRRRRRRCRUDRC
記録を復旧するCUDCUDCUDCUDCUDCUDRCUDC
試作を終了するRDRDRDRDRDRDRDRDRD

参照はR、取消は出席U。復旧のC/U/Dはバックアップ時点の状態へ戻す操作。終了時はすべてD。バックアップ世代の削除はWS07のD、試作終了による一括削除はWS09のD。
